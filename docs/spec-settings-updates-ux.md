# 设置页视觉优化：对齐靠结构、线条收敛（Spec v3）

> to-spec 流程产物；GitHub 仓库禁用 issues，落到本地 docs。已用浏览器对浅色+深色实际核验。
> 状态：已实施待提交。取代"块加线""整行分隔线"两个被否方向。

## Problem Statement（基于真实截图诊断）

1. **满眼是线**：给每个 setting-row 加整行底部分隔线后，行底线与输入框/下拉描边是两条平行同色线，用户要反复分辨"哪条是分隔、哪条是控件"，视觉噪音大。
2. **动作被线切开**：软件更新页「更新通道」与「检查更新」本是同一动作链，被一条横线分成两块。
3. **首行偏位**：行底 padding + 分隔线让每页第一项与其他项垂直节奏不一致。
4. **右缘不齐**：各行控件宽度不一，未统一到一条右缘线。

## Solution（以人为本：对齐靠结构不靠线）

- **撤销整行分隔线**：让控件自身描边成为唯一的线，不再有两条平行线撞色。
- **对齐靠结构**：固定标签列宽 + 所有右侧控件统一贴右缘（`justify-self: end`）+ 行内垂直居中。肉眼自然横扫，无需引导线。
- **检查更新留在原位**（更新通道下方独立行），仅因去掉横线而与通道在视觉上重新连成一组，不挪动位置。
- 首行偏位随撤销行底 padding 自动恢复。

## Implementation Decisions

- `.setting-row`：去掉 `padding-bottom` 与 `border-bottom`（撤销分隔线）；保留 `> :last-child { justify-self: end }` 把控件贴右缘。
- ≤720px 单列断点下控件回 `justify-self: start`。
- 保留：updates-panel（软件更新分区无描边、浅底更新卡片、隐藏该页标题分隔线、btn-sm、箭头对齐）、默认分区 `'hotkeys'→'ui'`。
- 不再引入任何形式的行引导线/分隔线（块加线、整行线均已否）。

## Testing Decisions

- 纯样式调整，按约定不强制加测试。跑 settings.test.ts + update-notes.settings.test.ts（20 通过）+ vue-tsc（exit 0）。
- 浏览器浅色+深色截图复核：线条消失、控件整齐贴右、通道与检查更新连组、首行居中。

## Out of Scope

- 不重构 setting-row 的 grid 双列结构；不动其他分区卡片式子区块；不引入任何行引导线。
