# UI 动手前核对清单

写或改任何前端 UI 代码**之前**，把下面 5 条从头到尾扫一遍。每条都能追溯到
`DESIGN.md` 的某条原则；这张清单不替代它，只负责把"动手前最容易跳过的判断"
钉在台面上。

判断依据（为什么）查 `DESIGN.md`；选哪个零件（用什么）查
[`ui-components.md`](./ui-components.md)。两份文档的数值都以
`glimpse-frontend/src/styles/main.css` 为唯一事实源。

## 1. 这个场景在重要性梯队里排哪一级？

先分级，再决定醒目程度。Glimpse 的梯队是：主路径（搜索/召回，深蓝 primary）
> 捕捉动作（截图，砖橙 accent，只此一处）> 结构与承载（中性色+1px 边框）
> 次级信息（`--color-text-muted`）。

- 常规提示、低频配置**不许**拿危险/警告的视觉语言（警示图标、大投影、
  字重 600 的主按钮）。典型反面：把"发现新版本"塞进带琥珀警示三角的确认壳。
- 依据：`DESIGN.md` 原则 1、2。

## 2. 有现成组件吗？有就只加 variant，不新造平行组件

动手前先查 [`ui-components.md`](./ui-components.md) 的选型表。

- 有现成组件但样式不合场景 → **给它加 variant/prop**，不要为单个页面复制一
  套平行组件。改共享组件时，必须逐一核对全部调用方不回归。
- 确认没有才新造，新造也必须复用现有 token。
- 依据：`DESIGN.md` 原则 2、四、Don'ts"不为单个页面发明一套平行组件"。

## 3. 控件高度落在三档里的哪一档？

不许发明第四档。

| 档位 | token | 用在哪 |
|---|---|---|
| 28px | `--control-h-sm` (1.75rem) | 顶栏图标按钮、导航按钮、分段器、设置区苗条控件 |
| 32px | `--control-h-md` (2rem) | 常规按钮、搜索工具区（默认档） |
| 40px | `--control-h-lg` (2.5rem) | 仅大目标：图片翻页箭头、大图关闭 |

- 依据：`DESIGN.md` 原则 5"密度即效率"、附录控件规格；数值以 main.css 为准。

## 4. 同排的同梯队元素，尺寸和 hover 跟邻居逐一比对过吗？

把新控件放到它实际出现的位置，跟左右邻居并排看。

- 同梯队的相邻控件，高度、圆角、hover 反馈**必须一致**。典型反面：顶栏
  下载图标裸用 40px `shell-icon-button` 还附带 transform 位移，而旁边的
  设置齿轮是 28px、纯背景 hover——点击区和动画区都对不上。
- 依据：`DESIGN.md` 原则 4"稳定胜于惊喜"、原则 2"同一梯队同一套表达"。

## 5. 用真实内容把它撑开、滚一滚了吗？

设计文档管不住实现缺陷，只有亲手验证能抓。

- 拿**真实/极限内容**（长文本、长列表、窄宽度）把新组件撑开：会不会横向
  滑动？滚动条是不是常驻杵在那很丑？该隐藏就隐藏（`scrollbar-width:none`
  + `::-webkit-scrollbar` 隐藏），该滚动驱动就别常驻。
- 同时核对：浅色/深色两主题、窄屏、键盘焦点、禁用态。
- 依据：`DESIGN.md` 原则 3"状态永远清晰可辨"、Do's"同时检查浅色、深色、
  窄屏、键盘焦点和禁用状态"。
